# Darwin (macOS) Compatibility Guide

This Claude instance is the designated **macOS/Darwin compatibility guardian** for Yuzu. The `cross-platform` agent loads this document on any change that may affect macOS builds, tests, or runtime behavior.

CLAUDE.md keeps a one-line pointer; this document holds the workflow and the standing pitfalls table.

## Standing workflow

When Windows-originated changes land on `origin/dev`, the standing reconciliation workflow is:

1. `git fetch origin && git status` — confirm branch state.
2. `git pull` — fast-forward to latest dev.
3. `git diff HEAD~N..HEAD --stat` — review what changed.
4. Identify which previous Darwin fixes are still present in the new tree.
5. `meson setup build-macos --reconfigure ...` if `meson.build` changed.
6. `meson compile -C build-macos` — fix any new compile errors.
7. `bash scripts/run-tests.sh all` — fix any new test failures.
8. Commit clean with a Darwin-fix commit message.

After **any** cross-platform change, always run `bash scripts/run-tests.sh all` on Darwin before committing.

## Standing Darwin pitfalls

| Area | Issue |
|---|---|
| SparkEngine (ADR-0021) | **SparkEngine starts with ZERO mechanisms on macOS — this is expected, not a fault.** All three factories (`make_{file,registry,service}_mechanism()`) return `nullptr` on Darwin: File/Registry are Windows-only, Service is Windows-SCM + Linux-sd-bus. `start()` with an empty mechanism map succeeds (the wheel thread runs, nothing is armed). The agent correctly reports `spark_running=1` with an **empty** `spark_mechs` CSV, and the server emits **no** `yuzu_fleet_spark_mechanisms{os=darwin,...}` series at all. **The absence of those series IS the correct signal — do not "fix" it by registering a stub mechanism**, and do not read the absence as breakage. (A Linux build without libsystemd, e.g. musl/Alpine, takes the identical path.) |
| Path comparisons | macOS `/var` → `/private/var` symlink: always call `fs::canonical()` on both sides before comparing paths in tests. |
| Shutdown self-pipe (`pipe2`) | **macOS has no `pipe2`.** `agents/core/src/shutdown_watcher.hpp` uses `pipe2(fds, O_CLOEXEC)` under `#ifdef __linux__` and falls back to `pipe()` + two `fcntl(F_SETFD, FD_CLOEXEC)` calls elsewhere — which leaves a window where a concurrent `fork`/`exec` inherits the fds, the exact race `pipe2` exists to close. The `fcntl` results are therefore checked and the watcher **fails closed** (degrades to the hard-exit handler — killable everywhere incl. pid 1) rather than shipping a pipe whose fds leak into every subprocess. **The window is currently unreachable, but for a reason the code does not state and you must not break:** the watcher is constructed in `main()` BEFORE `agent->run()`, and every fork/exec source (the trigger engine, plus the `ioc` / `firewall` / `services` / `software_actions` / `wol` / `license_scan` plugins) is only started INSIDE `run()`. Move the watcher's construction later and the race becomes real. Two further Darwin traps in the same file: `O_NONBLOCK` goes on the **write end only** (a non-blocking read end makes the watcher exit instantly and SIGTERM silently stops being graceful while the process still dies via the default disposition — so nothing *looks* broken), and a bare `mktemp -d` is a usage error on BSD, which is why `scripts/test/agent-shutdown-smoke.sh` always passes a template. **What IS verified on macOS:** the fallback compiles on every PR (`meson compile -C build-macos`) and `tests/unit/test_shutdown_pipe.cpp` (guarded only by `#ifndef _WIN32`) RUNS on the macOS CI leg. **What is NOT:** the end-to-end smoke script — it is portable (it probes with `ss`/`lsof`/`netstat` and strips BSD's full-path `ps -o comm=`), but it is only wired into the **Linux** CI leg, so it has never actually run on Darwin; and no shutdown timing has ever been measured on real macOS hardware. `scripts/run-tests.sh` now SKIPS it on Darwin explicitly, because it has never been validated there — running an unvalidated script under a doc that mandates running it was the worst of the available options. Wiring it into the macOS CI leg is tracked in the governance follow-ups ledger (.spark-issues/governance-followups.md item 20) pending an issue number. |
| SQLite concurrency | All stores must open with `sqlite3_open_v2()` using `SQLITE_OPEN_READWRITE \| SQLITE_OPEN_CREATE \| SQLITE_OPEN_FULLMUTEX` flags — never plain `sqlite3_open()`. Application-level mutexes (`shared_mutex`) are retained as defense-in-depth and are **required** (not optional) for stores with cached prepared statements, because FULLMUTEX does not make bind-step-reset sequences atomic. |
| Firewall state (pf ≠ Application Firewall) | **pf is NOT the macOS firewall.** `pfctl -s info` reports the BSD packet filter — off by default and unrelated to the Application Firewall that System Settings toggles; reading `/dev/pf` also needs root. The user-meaningful signal is `/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate` (unprivileged; `(State = N)`: 0 disabled, 1 enabled, 2 enabled + block-all — parse the number, not the prose). The `firewall` plugin reports the Application Firewall as primary (`backend\|appfirewall`) with pf demoted to a secondary `pf\|<state>` row (parsers: `agents/plugins/firewall/src/firewall_parsers.hpp`); unreadable checks report `unknown`, never a false-safe value. |
| Erlang rebar3 ct | Always pass `--dir apps/yuzu_gw/test` together with `--suite` flags. |
| `curl -f` in tests | Do **not** use `-f` where 4xx is an acceptable response — it causes `|| echo "000"` fallbacks to contaminate the status code variable. |
| `prometheus_httpd` | Use `start/0` with `application:set_env(prometheus, prometheus_http, [{port, P}, {path, "/metrics"}])` — `start/1` does not exist. Call `application:ensure_all_started(prometheus_httpd)` first so `prometheus_http_impl:setup/0` runs before the first scrape. |
| nstat kernel control (TAR netqual + tcp lifecycle) | macOS netqual and tcp-lifecycle capture share one `NstatClient` (`agents/plugins/tar/src/tar_netqual_nstat.cpp`) that opens the private `com.apple.network.statistics` **kernel control** — a `PF_SYSTEM`/`SYSPROTO_CONTROL` socket (`<sys/kern_control.h>`), **not a framework** — so unlike Endpoint Security it needs **no Apple entitlement** and no full-Xcode-SDK gate. The trade-off: it is a **private, undocumented, layout-UNSTABLE wire protocol**. `nstat_msg_hdr`/`nstat_tcp_descriptor`/`nstat_counts` are transcribed from XNU's open-source `bsd/net/ntstat.h` at the minimum-target release (macOS 13.3, `__NSTAT_REVISION__` 9 / tag `xnu-8792.41.9`); Apple has changed field order and struct size across releases with no ABI promise. **Two guards, in layers:** (1) every transcribed struct pins its `sizeof` AND the `offsetof` of each field the decoder reads with a compile-time `static_assert` set to the literal XNU offset — because the header is XNU-private and cannot be `#include`d, this is the closest feasible cross-check and it catches any future reorder/width/padding drift at build time (a hand-transcription slip is exactly how the first cut shipped wrong constants and layouts); (2) a runtime length self-check validates each decoded message's declared length against `sizeof` and **falls back to `capture_method=none` on mismatch rather than emit plausible-but-wrong rtt/loss numbers** — a failed check must never be treated as a decode. The SRC_DESC check is a `>=` FLOOR (not exact) so a larger later-OS descriptor still decodes: every field we read lives in the stable 13.3 prefix, ahead of the fields Apple appended (persona_id/uid). Separately, **root is required for system-wide flow visibility**: opening the kctl socket needs no privilege, but an unprivileged process reliably sees only its own process's flows, so a non-root agent reports the honest `none` rather than a silently partial capture (mirrors the Windows ESTATS admin-only posture). The `proc_pidfdinfo` poll is retained as the tcp-lifecycle fallback/seed, not replaced. |
| EndpointSecurity framework (TAR process stream) | `EndpointSecurity.framework` ships with the **full Xcode SDK only** — the Command Line Tools SDK omits it, so `dependency('appleframeworks', modules: ['EndpointSecurity'])` fails on a CLT-only host. The TAR plugin meson (`agents/plugins/tar/meson.build`) detects it with `required: false`: present → compile the real ES client (`-DYUZU_HAVE_ENDPOINT_SECURITY`, link `bsm` for `audit_token_to_pid`); absent → `tar_proc_es.cpp` compiles its no-op path and the agent falls back to the `KERN_PROC_ALL` sysctl process poll. So a CLT-only dev box builds and the suite stays green; ESF streaming needs full Xcode. At **runtime** `es_new_client` additionally requires the `com.apple.developer.endpoint-security.client` entitlement (Apple-restricted, manual grant) + a signed/notarized binary + **root** (the LaunchDaemon already runs as root); without these `start()` returns false and the agent polls. **Status keys:** `process_stream_dropped` counts **userspace ring overflow** (the drain tick fell behind — not kernel-side ES drops), while `process_stream_kernel_dropped` counts **kernel-side** Endpoint Security drops detected as `seq_num` gaps; `process_capture_method` reports the live path. **Self-heal:** a NOTIFY-only ES client has no liveness API, so if it goes silent (no exec/exit) for longer than the idle threshold (~1h) the agent presumes it dead and re-arms the poll — deliberately long, because a quiet host is indistinguishable from a dead stream and a false trip drops a healthy stream to the inferior poll. **Parity gap:** the stream subscribes `NOTIFY_EXEC`/`NOTIFY_EXIT` only — a fork-without-exec child is invisible until it exits (Windows ETW fires on every create); `NOTIFY_FORK` capture is deferred (#1455). **NOTIFY-only is a hard rule — never subscribe AUTH events:** an AUTH subscription makes every exec on the host block on the agent's verdict (gates exec system-wide); a slow or wedged agent would stall the machine. macOS process rows are **names-only on both the ES and poll paths** (the poll blanks the `proc_pidpath` image it would otherwise store in `cmdline`). |

## Per-OS build directory

The Yuzu source tree is built from multiple hosts (WSL2 Linux + native Windows on the same physical machine, plus this macOS dev box). `scripts/setup.sh` selects the canonical `build-macos` directory automatically and refuses to reconfigure a directory whose recorded source path looks like a different host's. See CLAUDE.md `## Build` → `### Per-OS build directory convention` for the full rule.

## macOS `/test` prerequisites

Before invoking `/test` (the pre-commit/pre-push gate skill) on a fresh macOS dev box, install:

| Tool | Install | Why |
|---|---|---|
| autoconf/automake/libtool | `brew install autoconf automake libtool` | vcpkg's libpq port (Postgres substrate, ADR-0006) runs autoreconf during `vcpkg install`; a fresh mac fails the configure phase without them |
| GNU bash 5+ | `brew install bash` | `mapfile` and `declare -A` are bash-4-only; stock `/bin/bash` 3.2 trips the version guards in `preflight.sh`, `perf-gate.sh`, `teardown.sh`, `test-fixtures-verify.sh` |
| Erlang/OTP 28 | via kerl (see `scripts/ensure-erlang.sh` or `scripts/darwin-activate-erlang.sh` if you've created a local shim) | Gateway build + EUnit + dialyzer |
| OrbStack or Docker Desktop | GUI / `brew install --cask orbstack` | Phase 1 image build + Phase 2 upgrade-test. Without a running Docker daemon both phases SKIP gracefully (the rest of `/test` continues), but you cannot exercise the upgrade-test surface |

UAT bring-up is `bash scripts/start-UAT.sh` (cross-platform; `linux-start-UAT.sh` is a back-compat shim). The `_portable.sh` helper auto-discovers OrbStack at `/Applications/OrbStack.app/Contents/MacOS/xbin/docker` and Docker Desktop at `/Applications/Docker.app/Contents/Resources/bin/docker` — you do not need either on PATH globally.
