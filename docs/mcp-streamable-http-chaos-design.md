# Chaos Test Design — MCP Streamable HTTP (track 2f)

Gate 5 synthesis from the 2026-07-11 governance run on the Decision 15 docs commit. Each track 2f implementation PR **must carry the automated reproductions mapped to it below** (P0 = blocks that PR's merge); the letters refer to Decision 15's pre-commitments (a)–(k) in `docs/adr-1005-execution-plan.md`.

## Scenarios

- **CH-1 — Terminal never arrives + cap expiry** (verifies f). Kill the sole target agent mid-`execute_instruction`-with-progressToken; short test cap. Success: stream ends with a machine-parseable A4-shaped final frame carrying partial status + "execution continues server-side", structurally distinguishable from success; `get_execution_status(execution_id)` still serves durable state. **P0 PR 3.**
- **CH-2 — Ring wrap + mid-stream disconnect + resume** (verifies d+f). Sever TCP mid-progress, wrap the replay ring while disconnected, let execution finish. (a) In-window resume replays missed frames AND the final JSON-RPC response (pending final frame survives eviction — bounded: one per streamed request). (b) Past-window resume → 404 → re-initialize, never a silent gap; result fetchable by `execution_id`. **P0 PR 2; re-run at PR 3** (final-frame exemption exists only once the bridge does).
- **CH-3 — Restart + duplicate-dispatch temptation** (verifies g+j). Restart server with live session + in-flight streamed mutating tool; real client (MCP inspector, mcp-remote) hits 404. Success: client re-initializes; mutating execution count unchanged (no blind re-POST); fresh per-session event ids, no cross-restart `Last-Event-ID` collision honored. **Id-namespace half P0 PR 2; real-client half P0 PR 5.**
- **CH-4 — Revocation vs auth-backend outage** (verifies c+i). N live streams, ≥2 principals; (a) revoke one token; (b) blackhole the auth backend. Success: (a) revoked principal's streams terminate within one heartbeat tick, others survive; (b) no stream dies inside the grace window during an outage; post-grace terminations carry a distinct reason; re-validation QPS is O(cache-refresh), not O(streams×tick). **P0 PR 2; metric assertions re-run P0 PR 4.**
- **CH-5 — Cap exhaustion on shared token** (verifies d+h+j). Drive one principal to the per-principal cap, a second to the global cap. Success: cap+1 `initialize` rejected with an A4 error; no live session/stream evicted; streamed POSTs debit the same budget as GET channels. **P0 PR 2** (session-cap-rejection half P0 at **PR 1** if session caps ship there — PR 1's `mcp.session.reject` cap-hit audit verb implies they do).
- **CH-6 — Worker-pool starvation** (verifies h). Saturate held-open responses (GET + streamed POSTs) at exactly the caps; drive plain REST + legacy plain-POST MCP concurrently. Success: plain-path latency within no-stream baseline (caps provably below the httplib pool size with margin); zero timeouts. **P0 PR 2.**
- **CH-7 — Kill switch + bounded shutdown**. (a) SIGTERM with live streams + in-flight bridge subscription → stop closes/joins all streams within a bound, no hang (cf. the PR #1311 shutdown-deadlock lesson), no orphaned `ExecutionEventBus` subscriber. (b) Restart under `--mcp-no-streaming`, client presents a prior session id → defined, documented response. (c) `--mcp-disable` stub answers GET/DELETE. **(b)+(c) P0 PR 1; (a) P0 PR 4.**
- **CH-8 — Session fixation + cross-principal oracle** (verifies a). `initialize` carrying a client-supplied `Mcp-Session-Id` is never adopted (fresh ≥128-bit id minted); principal-A's valid id under principal-B's token returns a 404 byte-identical to unknown-id, no gross timing divergence; per-request token auth enforced on every method. **Critical, P0 PR 1.**
- **CH-9 — Origin misconfig not silent** (verifies e). Hostile / absent / allowlisted Origin plus an empty/typo'd allowlist, across POST/GET/DELETE. Hostile rejected on every method; absent allowed (credential required); every reject visible in reason-labeled metrics. **Behavior P0 PR 1; metric assertion P0 PR 4.**
- **CH-10 — Reverse-proxy SSE buffering.** Stream through nginx with default buffering; reproduce the stall, prove the documented proxy config fixes it; heartbeats let the server detect the dead channel. **P1 PR 5.**
- **CH-11 — Strict-client 202 empty body.** A strict JSON-RPC client library sends a notification; 202-with-empty-body accepted without parse error. **P0 PR 5.**
- **CH-12 — Cancelled ≠ cancelled** (verifies j). `notifications/cancelled` mid-execution: close-frame states execution continues; execution completes and is durably recorded; cancellation audited. **Frame P0 PR 3; audit assertion P0 PR 4.**
- **CH-13 — Session soak** (verifies d). Nightly: thousands of mint/expire cycles + ring churn + compound CH-2+CH-4 (ring wrap + disconnect + revocation-during-resume); RSS bounded, TTL reaps idle sessions. **P2 nightly.**

## Streamed-POST scenarios (2f PR 3b, governance Gate 5 2026-07-27)

CH-14/15/16 landed with the rung and gate its push; the rest are tracked follow-ups.

- **CH-14 — Stalled writer + cancel storm** (verifies h). Park a writer mid-close-frame with a blocking `WriteFn`; assert an unrelated publisher is not blocked behind it, and that a retried cancel neither waits nor double-audits. **P0 PR 3b — LANDED** (`test_mcp_stream_bridge.cpp`, `[ch14]`). Also covers the mid-tick cancel, which this rung NARROWED rather than closed: `take_post_batch` now flips `closed` at the decision point, so a cancel arriving after the bridge has handed back a final answers `kNoOp` and does not claim a detach. The residual window is the batch handover alone - a cancel landing between the pump's top-of-tick `closed` read and that flip still wins `close_post_sink`'s exchange and audits a detach while the pump goes on to write the final and close `kCompleted`. `[ch14b]` pins the post-handover instant only; the handover window itself is a tracked follow-up (close it by flipping `closed` inside the same `rec->mu` hold in which `project_record` commits the terminal).
- **CH-15 — Pin slots are a concurrency limit, not a lifetime quota** (verifies d+f). Twelve SEQUENTIAL completed streamed calls on one session; `pinned_count()` returns to 0 after each final reaches the wire. No fault injection — pure sequencing, which is why the original defect survived every fault-injection test. **P0 PR 3b — LANDED** (`[ch15]`).
- **CH-16 — Progress arrives on publication, not on the tick** (verifies the rung's headline claim). A deliberately long tick; publish once; assert first-byte well inside it. Pre-fix this measured the full tick, because the wake channel set nothing the pump's predicate read. **P0 PR 3b — LANDED** (`[ch16]`).
- **CH-17 — Post-dispatch store outage.** Pause Postgres between dispatch and `refresh_counts` on a streamed `execute_instruction`; hold past the response cap. Success: the 500 body carries `execution_id` (landed as a unit assertion), the fleet execution count is 1 after a conforming client's retry policy runs, and the shared budget does not saturate for the outage plus the full cap. **Body half P0 PR 3b — LANDED; container half P1, follow-up.**
- **CH-18 — Exactly one answer per request id.** Fault the bind/install path, answer plain JSON, then resume the GET channel with `Last-Event-ID = 0`. Success: no second `{"id":X,...}` for that id across the POST wire and the resume; a post-install throw does not yield 500-plus-live-SSE. **P1, follow-up** (needs the demote-to-get-only seam).
- **CH-19 — Bounded shutdown with live streamed POSTs.** SIGTERM with 4 live streams. Success: exit within one tick rather than one response cap per stream; every `mcp.stream.attach` row has a matching close row; the close frame names a shutdown reason, not `cancelled`. **P1, follow-up** (needs the pump stop-token).
- **CH-20 — Buffering proxy + grace-expiry mass close.** Front the server with a non-nginx proxy that buffers, kill the client mid-stream, and blackhole the auth backend so every stream reaches its grace deadline together. Success: dead-peer detection still fires or the limitation is documented; no synchronised mass close; the retry wave is bounded. **P2, follow-up.**
- **CH-21 — Streamed soak.** Nightly: 10k mint/cancel/complete cycles. Success: `global_record_cap` never wedged, pin slots return to 0 at quiesce, RSS bounded (regression cover for the request-body retention fix, whose pre-fix headroom was +512 MiB held for a full cap). **P2 nightly, follow-up.**

- **CH-22 — The credential-check interval survives a poke.** Freeze an injected clock just short of the next check, then take a SECOND pump tick. Success has THREE parts, because the first alone is not the contract: (1) the pump waits only until the check falls due - pre-fix this measured a full extra tick (5.0s against a 50ms budget), because the wait restarted from each WAKE while the gate counted from the last CHECK, so one poke before the boundary followed by silence stretched the bound to nearly 2x; (2) the check then ACTUALLY RUNS once the clock reaches the boundary - asserting only a shortened wait would stay green against an implementation that woke early and skipped the check, which is the regression this scenario exists to prevent; (3) a sub-millisecond remainder does not round DOWN to a zero budget - flooring returned instantly, fell through to the unconditional heartbeat write, and let the caller re-enter in a tight spin emitting heartbeat frames at the client until real time crossed the boundary. **P0 PR 3b — LANDED** (`[ch22]`). Note every other revocation test closes on tick ONE, where `next_check_` is the epoch and the check is always due; the defect lived strictly on the second tick. Parts (2) and (3) were added after two adversarial reviewers independently found that part (1) alone did not prove the bound.

**Harness note.** CH-14/16 are only expressible because `BlockingWire` (`test_mcp_stream_bridge.cpp`) can park a writer mid-write and hand back a deterministic "the peer stopped reading" handshake. The in-process handler fixture never runs a content provider (#438), and that gap is why a held-lock-across-socket-write, an inert wake channel and an incomplete close window all survived TSan-clean-3x, three adversarial review rounds and 89k assertions. Any future streamed-surface scenario should extend that harness rather than assert against the fixture.

## Accepted risk (no scenario)

Dual-stack replay-window divergence (`/api/v1/events` vs the MCP session ring retaining different histories for one execution): accepted — durable stores remain the forensic truth; PR 5 documents it in one sentence.
