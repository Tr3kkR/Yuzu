## The invariants, in full

**`execution_artifacts` plugin — Windows execution-evidence reads (ShimCache/AmCache/Prefetch).** Three read-only actions, all on the `Forensics` securable (`AdminOrApproval`, single-target, audited, default-off via the server-side plugin-config kill switch). CATASTROPHIC-IF-VIOLATED: (1) a truncated/malformed/unknown-version/over-cap artefact reports `constrained` with a named reason — never an empty success, never an exception across the plugin ABI (the entry-point `try/catch(...)` frozen-seam rule). This is a per-ARTEFACT contract, not per-file: Prefetch enumerates up to `kPrefetchMaxFiles` individual `.pf` files, and a single file's parse failure reports its own `prefetch_error`-prefixed row (file then reason, pipe-delimited after the discriminator, same shape as every other row this plugin emits) (folded into the terminal typed status via `ConstraintAccumulator`, clause 2) rather than aborting the whole `prefetch` action — every OTHER file's real row still ships. Within one file's own parse, though, the rule is absolute: `parse_prefetch` must validate EVERY declared volume entry (not just the first — the class of defect that shipped once, a parser that only read entry 0's file-reference count and silently under-reported/zeroed every subsequent entry's). (2) every failure-reason token accumulates through the shared `yuzu::shared::ConstraintAccumulator` (`agents/shared/constraint_accumulator.hpp`) — never a local per-plugin reimplementation; (3) every AmCache hive-loading caller serialises through the single process-wide `offline_hive_mutex()` (`agents/core/include/yuzu/agent/offline_hive_mutex.hpp`), held for the ENTIRE privilege-bearing span (copy → `RegLoadAppKeyW` → enumeration → `RegCloseKey`) — a second lock primitive for the same hive is the exact drift this seam exists to prevent. This plugin holds it via `yuzu::agent::ScopedOfflineHiveLock("execution_artifacts")` (the hardened, wait/hold-logging RAII wrapper merged via `fix/offline-hive-mutex-exception-safety`), the same primitive `with_user_hive()`'s five other callers (registry/installed_apps/license_scan/tar/autoruns) share — a bare `std::lock_guard<std::mutex>(offline_hive_mutex())` is the exact drift `ScopedOfflineHiveLock` exists to replace; do not reintroduce it here. (4) paths and hashes only, never file contents — AmCache's raw `Amcache.hve` copy is a necessary INTERMEDIATE (RegLoadAppKeyW needs a real file), staged in a per-dispatch, random-named, owner-verified scratch directory under `agent.data_dir` and removed before the action returns; it is never itself an output row.
