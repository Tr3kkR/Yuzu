# 0021 — Sparks as the sole detection layer; Guardian, DEX, and Reflex as sovereign consumers

Supersedes the previously-considered incremental-migration posture (converge detection mechanisms opportunistically, one subsystem at a time) in favor of the full-convergence rebuild recorded here. Also supersedes §11.1 of `docs/yuzu-guardian-design-v1.1.md` as the authoritative approval-workflow design (see Decision 9).

## Context

Detection machinery is implemented three times on the agent: Guardian's IGuards (kernel/bus-notification — `ReadDirectoryChangesW`, `RegNotifyChangeKeyValue`, SCM notify, systemd sd-bus — server-pushed, persisted, one thread per armed guard), the TriggerEngine's watchers (plugin-authored at init, fire-and-forget, non-persistent, predominantly polling — its registry trigger arms an async RegNotify checked on a poll loop), and DEX's collectors (event-log/WER/poll). Response capability is limited to Guardian's in-thread enforce; there is no way to bind a detection to an arbitrary action. Server-side, event reaction is fragmented (`dex_alert_router` covers ruleless observations only; rule-bound drift events route nowhere) and event-*launched* workflows are proposed-but-unbuilt (a REST/cron-launched `WorkflowEngine` exists). Yuzu is greenfield (small test labs, no customers), which makes a core rework cheapest now.

## Terminology

- **Spark** — a use-case-agnostic detection trigger: a type plus parameters describing a device condition to watch (file change, service status change, registry change, disk threshold crossing, interval). An authored spec; "armed" = its watcher is running. Consumers receive events, never watcher instances.
- **Reflex** — an agent-local binding from a Spark to one or more Reactions, executed on the device the moment the Spark fires, with or without server connectivity.
- **Reaction** — one plugin invocation (plugin, action, parameters) within a Reflex's chain; runs sequentially, may be gated on the prior Reaction's result.
- **Reflex Set** — the deployable unit for Reflexes: a named collection with management-group assignment, exactly the Baseline grammar. Individual Reflexes never deploy alone.

## Decisions

1. **Spark is the platform detection primitive, and SparkEngine is the agent's *only* detection layer.** A Spark is a use-case-agnostic trigger spec (type + params → events); consumers own the meaning of its events. Full convergence, not opportunistic: *all* detection — Guardian guards, TriggerEngine watchers, DEX collectors — becomes spark types. SparkEngine multiplexes watchers by mechanism (completion port, notification pump, **wait-pool for event-handle APIs** — `RegNotifyChangeKeyValue` cannot ride a completion port and naive waits hit the 64-handle cap — and a timer wheel), not by rule, and dedups arming across consumers.

2. **Consumer sovereignty.** Guardian (Spark + Assertion + Observe/Enforce + compliance census), DEX (Spark → curated observation, privacy drops, rate caps), and Reflex (Spark → Reactions + escalation) are *sibling* consumers. They never converge: Guardian is not a specialized Reflex, DEX is not an empty one. Rejected alternative: Reflex as the general form with Guardian/DEX as flavors — conceptually unifying, but it makes the safety-critical subsystem a special case of the general-purpose one, and every Reflex feature becomes a potential Guardian behavior change.

3. **Two subscription tiers preserve microsecond enforce.** *Inline* handlers run synchronously on the watcher thread — µs-bounded, never blocking, never invoking a plugin; Guardian enforce is the only intended occupant. Everything else (Reflex, DEX, event emission, Guardian reporting) is *queued*: per-consumer queue + thread, so consumer code never runs on a watcher thread and a blocked consumer (a popup open for minutes) cannot stall detection or another consumer. **The inline contract is enforced, not conventional**: inline registration is a core-internal API unreachable from the plugin ABI, its handler signature receives the event plus a narrow enforce capability only (no dispatcher, no plugin-host handle — a plugin call is a compile error), and a runtime watchdog (inline-handler duration histogram + stall counter) feeds the resource gate.

4. **Reflex / Reaction / Reflex Set.** A Reflex binds a Spark to a deliberately tiny chain of Reactions (plugin invocations, sequential, optionally gated on the prior Reaction's result) with an escalation policy (so many chances over so much time, then act — or don't). Real orchestration belongs to server Workflows reacting to Reflex events — a Reflex never grows into a workflow. Reflexes deploy only as members of a **Reflex Set** (assignment semantics identical to Baselines): the platform grammar is *building blocks never deploy alone; named, assigned collections are the deployable unit*. Prerequisites generalizes to any Baseline/Reflex-Set member. **Consent invariant, mechanically enforced:** on user devices Yuzu never takes consequential action without end-user consent. This is a *preventive* gate, not an authoring convention: the platform gains an **operator-declared device classification** (workstation / server — declared, never inferred), and the policy compiler **rejects** `proceed`-on-exhaustion escalation on consequential Reactions whose resolved scope can include workstation-class devices (an *unclassified* device is treated as workstation-class — fail-closed) — an extension of the existing `dangerous_*_in_spec` single-chokepoint pattern, never a parallel gate. Server-scoped variants may proceed on exhaustion.

5. **Capability lives in plugins; policy lives in bindings.** Plugins provide actions and may *implement* spark types (contribute detection machinery, e.g. an ETW session), but never decide when they run: `yuzu_register_trigger` retires (no permanent shim — flag-day, see 8), and every self-initiated agent activity becomes a declaratively-bound spark. Built-in schedules (TAR snapshot pumps etc.) ship as embedded-content Reflexes — visible, tunable, disableable; **DEX's default observation set likewise ships as embedded default content** so a fresh agent observes out of the box, pre-first-push. **Trust boundary:** plugin-implemented spark watchers run isolated on their own threads/queues, never on shared mechanism threads; the inline tier is restricted to core-built spark types; Guardian consumes core spark types only (or, later, provenance-labeled events it policy-gates) — a buggy or compromised plugin must not be able to stall or fabricate the compliance plane. "What does this agent do on its own?" is answered by enumerating armed sparks and their bindings — one inventory for operators, auditors, and works councils.

6. **One event spine, one event router, server-side.** All event families (Guardian drift, DEX observations, Reflex outcomes) land in a single event store with a first-class `family` discriminator (retiring the `__observation__` rule-id squat), born on PostgreSQL (per ADR-0006/0008; store contract ADR-0012), with per-family retention. **Admission rule:** the spine admits *episodes and edges* (agent-side rate caps, dedup, escalation outcomes) — never samples; sample-grade data stays on the agent's SQLite edge warehouse per ADR-0004. One router at the ingest chokepoint maps events → notification, webhook, or **launching a Workflow** scoped to the source device (building the proposed-only event-launched-workflow capability, once). `dex_alert_router` and `dex_blast_radius` become router consumers/feeders rather than a pre-router side-channel, and the router honors the executions-ladder one-bus/one-taxonomy invariant. Rejected: per-family stores/routers — three configs, and the workflow-trigger gap solved three times or never.

7. **Declarative content plane; per-consumer GUI.** Sparks, Guards, Baselines, Reflexes, Reflex Sets, and event routes are YAML-defined content (`yaml_source` authoritative), shippable in packs, with REST CRUD + MCP tools; dashboard forms (DEX / Guardian / Reflex tabs) are round-tripping views over the DSL. North star: Yuzu fully headless, MCP-driven; the GUI is a view, never the model. This also closes the Baselines gap: today Baselines have a REST *read* surface but no management (CRUD/deploy) REST API.

8. **Compiled policy wire.** The server compiles every deployed unit targeting a device into ONE versioned per-device policy document (one generation counter, one reconcile, one census-trigger), replacing `GuaranteedStatePush`. **Compiler invariant: the compiler reads only deployed snapshots, never drafts** — a deploy from one consumer's tab re-asserts (byte-identical) but never advances another consumer's content; the agent applies differentially. The generation counter is a *reconcile trigger only*, never a compliance signal — Guardian's census stays keyed on per-rule state rows, since any consumer's deploy advances every targeted device's generation. Authoring stays per-consumer; the wire is compiled. Upgrade posture: flag-day (greenfield). **Known gap, accepted greenfield-bounded:** a not-yet-upgraded agent keeps enforcing cached policy but is policy-deaf — it cannot learn that a Guard was revoked, and the retired push channel cannot clear it. Flag-day completion criterion: all lab agents upgraded or decommissioned (enumerated via the census) before any dangerous content deploys post-flip. The `__guardian__` KV cache carries the enforce set across the upgrade gap: the new agent must read the old cache format (preserving A2 re-arm continuity) or the ADR's implementer must surface the unenforced window explicitly. From the first customer onward, protocol changes must support rolling upgrade.

9. **Two-person approval, gated at deploy, digest-bound.** The approval workflow is built now, not deferred, **extending the existing shared `ApprovalManager`** (also used by MCP tier approvals — separation-of-duties stays one mechanism an auditor tests once). Any deploy whose unit contains dangerous content (dangerous enforce per the existing H1 taxonomy, extended with dangerous Reactions — state-changing on user devices, quarantine-class, interactive) requires approval by a **different principal** — evaluated across all identity surfaces (session, API token, MCP principal) and distinct from both the last content editor and the deployer. Approval binds a **canonical content digest** computed over member content + parameters + escalation policy + **assignment scope** — not a member-ID list — so editing a member's parameters or widening the assignment invalidates approval. The policy compiler **recomputes and compares the digest at every compile** and fail-closes on mismatch or absence (this digest-match check, not an `approved` flag, is what closes the approve→compile TOCTOU) — replacing today's silent enforce→audit downgrade. **Break-glass** is retained as designed in §11.1 (emergency single-principal override with mandatory justification and a `critical`-severity audit event), now applying to the unified approval flow; a break-glass override mints an approval record bound to the same canonical digest, so a subsequent edit re-requires approval. Reflex gets its own RBAC securable. One-time flag-day triage: existing deployed rules that ship today via the silent downgrade must be re-approved or re-authored.

10. **Privacy posture (rebuild requirements, not follow-ups).** Reflex outcomes record end-user *choices* — behavioral PII. (a) Outcomes carry the minimum: button choice + timestamps + reaction results, never free-text input; outcomes are device-scoped — user identity (SID/username/user paths) is never recorded, per the shipped DEX posture. (b) Per-device Reflex history is an access-audited surface via the `rest_audit.hpp` chokepoint. (c) What-can-prompt-users-where is a report over deployed content. (d) Operator-configurable TTL on Reflex outcomes. (e) Fleet dashboards aggregate-first with the shipped small-cohort floor (`kDexCohortFloor` precedent — an aggregate over 1–2 devices is a de facto per-device view); per-device drill audited. The remaining works-council enablement items (per-category collection toggle, individual-view kill switch, pseudonymization) are **deliberately deferred** to the works-council enablement backlog, not undiscovered omissions.

11. **Landing: one big rebuild.** A long-lived integration branch; internally a governed PR ladder (SparkEngine → consumers → ABI → server surfaces), reviewed against this ADR, with each rung's governance report retained as change-management evidence (SOC 2 Workstream F). Merged to `dev` atomically once three gates pass: a **parity gate** — Guardian §24 invariant tests, DEX obs_type stream *semantically equivalent on scripted scenarios* (same obs_type set, per-type counts within recorded tolerance bands — poll-latch and rate-cap timing make byte-identical streams unachievable), TAR pumps intact, three-OS UAT; a **resource gate** — idle CPU, wakeups/sec, thread count, RSS, old vs new, via the existing `/test` perf machinery; and an **evidence-continuity gate** — audit verbs and metric labels preserved or explicitly remapped, and any evidence queries re-pointed to the new event-family schema, so SOC 2 evidence automation does not silently break at the merge. Old and new worlds never ship interleaved.

12. **Out of scope.** `PolicyEvaluator` (server-polled, instruction-based compliance) is a separate evaluation plane from agent-resident Guardian and is untouched by this rebuild; unification, if ever, is a future decision.

## Consequences

- Guardian's enforce path moves house (guard thread → inline spark handler) but keeps its latency class; its §24 invariants, resilience strategy, and census semantics must be preserved verbatim — the parity gate exists to prove it.
- The plugin ABI changes shape (spark-type provision in, `yuzu_register_trigger` out) — an ABI-breaking release. This knowingly overrides the SDK's "Stable C ABI" promise and the `docs/cpp-conventions.md` ABI-version-bump gate; it is acceptable only because of the greenfield flag-day stance, and the bump follows that doc's migration-plan procedure.
- The gateway's generated protobuf modules regenerate for the new policy-push package (all three modules — `gateway_pb`, `management_pb`, `agent_pb`; the Register-field regen trap documented in the vendored `gateway/priv/proto/gateway.proto` ProxyRegister comment) as a planned work item.
- Detection threads drop from O(armed guards) to O(mechanisms) — the per-rule thread cost lives in Guardian's guards today; TriggerEngine's loops are already per-type — and polling coalesces onto a timer wheel. Measurably lighter at rest, verified by the resource gate rather than asserted.
- Replacing the silent enforce→audit downgrade with fail-closed compilation is a deliberate security-posture upgrade: dangerous content is now blocked visibly at deploy, never quietly weakened at push.
- Everything the fleet does autonomously becomes enumerable, diffable text — the compliance/works-council answer becomes a query over content, not an investigation over code.
