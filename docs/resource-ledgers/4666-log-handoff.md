# Resource Ledger - #4666 PR-1 bounded async log hand-off primitive

This ledger lists every thread, queue buffer, sink wrapper, and lock the PR-1 diff introduces, with
its owner and release path, for `agents/core/src/log_handoff.{hpp,cpp}`. A Resource Ledger is a
policy-floor artifact (CLAUDE.md standing rule 2), so it is a standalone file rather than a line in a
PR description. Nothing else changes in this PR — no production call site installs this primitive
yet (`main.cpp`/`service_win.cpp`/`guardian_engine.cpp`/`guardian_spark_runtime.cpp` are all
untouched; that wiring is PR-2). Format follows
`docs/resource-ledgers/spark-criterion10-timing-instrumentation.md`.

## `agents/core/src/log_handoff.{hpp,cpp}`

| Resource | Owner | Acquire | Release | Failure path |
|---|---|---|---|---|
| `spdlog::details::thread_pool` (one bounded queue + one worker thread) | `LogHandoff::pool_` (`std::shared_ptr`), constructed directly via `std::make_shared` — **never** `spdlog::init_thread_pool()`, so no spdlog registry co-owns it | `LogHandoff::create_with_sinks()`, after every earlier throwing step has already succeeded (sinks wrapped, error handler bound) | `LogHandoff::teardown()`'s T1 (`pool_.reset()`); `~thread_pool()` posts a `terminate` message under the `block` policy and **joins** its one worker | A healthy sink drains in order and the join returns promptly. A wedged sink means the call simply does not return; bounded by the `ShutdownDeadlineGuard` `teardown()` constructs around T1–T3 (`kLogTeardownGrace` 2 s default), which fires `hard_exit(kLogTeardownExitCode=5)` on the WHOLE PROCESS if the grace elapses — see the header's TEARDOWN CONTRACT for why this differs from the plan's original "caller wires an external watchdog" phrasing (U5's own requirement pins the self-contained design). `~LogHandoff()` runs `teardown()` if it was never called explicitly (fail-closed, matching `OrphanExitGuard`). |
| **Fixed RSS cost of the pool's queue — NOT proportional to traffic.** `spdlog::details::circular_q` pre-allocates all `kLogQueueCapacity + 1` (8193) slots **at `thread_pool` construction**, each slot a `spdlog::details::async_msg` (`sizeof == 408` bytes on x64, measured against the vendored spdlog 1.17.0 headers: a `log_msg_buffer` — four owning `std::string`s for logger name/payload/short-filename/funcname plus the scalar `log_msg` fields — an `async_msg_type`, and an `async_logger_ptr`). | The `std::vector<async_msg>` inside `circular_q`, owned transitively by `pool_` above | Same moment as the pool itself — this is not a high-water mark, it is paid in full up front | Same as the pool's own release | 8193 × 408 bytes = 3,342,744 bytes = **3.34 MB (≈3.19 MiB)**, always, for the life of any constructed `LogHandoff` — including one built only for a unit test. This is a corrected fact from the plan's final review (the original v1/v2 draft undercounted it as "~6 MB, only under load"); PR-2's own resource-ledger update and `docs/user-manual/server-admin.md` must both state the real figure again when the primitive is actually installed in the shipped binary. Payload bytes beyond the fixed per-slot allocation (a queued message's formatted text) are additional, unbounded by this primitive, and are measured on the rig in a later PR — never asserted here. |
| `spdlog::async_logger` (name `""`, `overrun_oldest`) | `LogHandoff::logger_` (`std::shared_ptr`) | Same `create_with_sinks()` call, immediately after the pool | `teardown()`'s T3 (`logger_.reset()`) | Holds only a `std::weak_ptr` back to the pool (never a cycle). `sink_it_`/`flush_` throwing (pool gone, formatter/allocation exception) routes to the non-I/O error handler below, never escapes uncaught into caller code (spdlog's own `SPDLOG_LOGGER_CATCH`). |
| `StallObservableSink` wrapper, one per caller-supplied inner sink | `LogHandoff::wrapped_sinks_` (`std::vector<std::shared_ptr<StallObservableSink>>`); each wrapper owns its inner `spdlog::sink_ptr` by `shared_ptr` | Same `create_with_sinks()` call, one per element of the caller's `sinks` vector | `teardown()`'s T3 (`wrapped_sinks_.clear()`), which drops the last reference to both the wrapper and (transitively) its inner sink — final inner-sink destruction (e.g. a rotating file sink's `fclose()`) therefore also runs under T1–T3's watchdog | The wrapper's own state is two plain atomics (`in_flight_` counter via an RAII `WriteGuard`, `started_at_ticks_`) — no lock, no allocation, cannot itself fail. `log()`/`flush()` forward to the inner sink and let its exception propagate (the RAII guard still decrements on unwind). `set_pattern()`/`set_formatter()` forward unconditionally (the v1→v2 regression the final review caught — dropping this silently reverts `--log-format json` to the default text pattern; pinned by unit test U-json). |
| Non-I/O error handler state (`LogHandoff::ErrorState`: a `std::mutex` guarding a count + a 256-byte-truncated last-message string) | `LogHandoff::error_state_` (`std::shared_ptr<ErrorState>`), captured by value into the `set_error_handler` lambda | Same `create_with_sinks()` call | Object lifetime ends when both `LogHandoff::error_state_` and the logger's own captured copy (inside `custom_err_handler_`, released at `logger_.reset()` in T3) drop | Reached **concurrently** from the pool's one worker thread (a sink `log()`/`flush()` throw) and from any producer thread (a formatter/allocation exception, or "pool gone") — this is why it is a plain `std::mutex`, not a lock-free/single-writer scheme (a spec bug in an earlier draft, corrected in the final review). The handler itself is wrapped in its own `try`/`catch(...)` so an allocation failure while recording the error message cannot escape back into spdlog's error-handling machinery. |
| Global drain-lookup slot (`DrainHandle`: `owner` raw-pointer identity tag + `std::weak_ptr` to the pool/logger/each wrapped sink + a STRONG `std::shared_ptr<DrainGate>`) | File-local `std::shared_ptr<DrainHandle>` behind a function-local-static `std::mutex`, in `log_handoff.cpp`'s anonymous namespace — no header exposure | `LogHandoff::register_global_drain_handle()`, called once at the end of a successful `create_with_sinks()` | `LogHandoff::clear_global_drain_handle()`, called as the FIRST step of `teardown()` (T0), identity-checked against the calling instance so a newer instance's registration is never clobbered by an older one's teardown | Holds **only weak references to the pool/logger/sinks** — `drain_log_bounded()` locks a temporary strong ref for the minimum span of each read. **Fixed defect (#4666 PR-1 adversarial review, both reviewers independently reproduced with standalone repros): an earlier revision of this row claimed the residual race where `drain_log_bounded()` momentarily holds the pool's last reference was harmless — it was not.** `teardown_body()`'s own `pool_.reset()` could become a non-destructive ref-decrement while the drainer still held a copy, letting `teardown()`'s `ShutdownDeadlineGuard` cancel on a NORMAL scope exit before the real blocking work had happened — so the drainer's later release could be the one running `~thread_pool()`'s blocking join, on the drain thread, with no watchdog covering it. **Fix: the drain-reader lease** (`DrainGate`/`DrainLease`, held strongly by `DrainHandle`) — `drain_log_bounded()` holds a `DrainLease` for its entire pool-touching span (declared first, so it destructs last, strictly after every local pool `shared_ptr` it creates); `teardown()`'s T0 calls `LogHandoff::close_drain_admission()` (stop admitting new leases) before doing any teardown work, then — still INSIDE its own already-armed `ShutdownDeadlineGuard` scope, not after it — calls `LogHandoff::wait_for_drain_quiescence()`, which blocks until every admitted lease has released. Only then does `teardown_body()`'s `pool_.reset()` run, which is therefore GUARANTEED to observe the last reference itself: the blocking `~thread_pool()` join can now only ever happen on `teardown()`'s own thread, under its own watchdog. See the header's DRAIN-READER LEASE paragraph for the full proof. |
| `LogHandoff::construction_fault_for_test_` (`static inline std::atomic<bool>`) | Process-wide, test-only | Set by `set_construction_fault_for_test(true)` | Auto-consumed (reset to `false`) by the very next `create_with_sinks()` call, so it cannot leak into an unrelated later test | Production code never sets this; it exists purely to exercise the pool/logger-construction-failure return path without depending on the OS actually refusing to create a thread. |
| `ShutdownDeadlineGuard` (from `shutdown_deadline_guard.hpp`, reused unmodified) — a detached watchdog thread | Local to `teardown()`'s (or `teardown_with_action_for_test()`'s) stack frame; the watchdog's own detached worker thread is spawned via `io_detail::spawn_detached` (that primitive's own established orphan-exit contract, unchanged by this PR) | First statement inside `teardown()`'s/`teardown_with_action_for_test()`'s try block, after T0's deregistration/admission-close | RAII: the guard's destructor calls `cancel()` when `wait_for_drain_quiescence()` (drain-reader-lease wait) plus `teardown_body()` (T1–T3) both return normally, before the enclosing stack frame unwinds | If `wait_for_drain_quiescence()` never returns (a lease never releases) OR `teardown_body()` never returns (a genuinely wedged sink), the watchdog fires its action — `hard_exit(kLogTeardownExitCode)` in production, or a caller-supplied test callback via `teardown_with_action_for_test()` — after the grace elapses; the CALLING thread of `teardown()` remains blocked regardless (the watchdog terminates the whole process in production; the test-action variant is what lets U5/the BLOCKER-1 regression test observe the deadline firing without actually killing the test binary — the test then still has to release the gate itself so the calling thread's own `join()` can complete). |
| `DrainGate` (mutex + condvar + `active_readers` count + `closed` flag) | `LogHandoff::drain_gate_` (`std::shared_ptr`), also held strongly by the global `DrainHandle` above (a tiny, non-blocking-destructor control block — safe to hold strongly, unlike the pool) | `create_with_sinks()`, in the same "everything that can throw happens before the object exists" phase as `pool_`/`logger_`/`error_state_` | Object lifetime ends when both `LogHandoff::drain_gate_` and the global `DrainHandle`'s copy (cleared at T0) drop | Null-safe by construction: `close_drain_admission()`/`wait_for_drain_quiescence()` both no-op if `drain_gate_` was never assigned (a construction failure before that line, which cannot reach a live `LogHandoff` object per the "only now" comment in `create_with_sinks()`). |

No production code path creates either double. |

## Trigger rows and invariants this change was checked against

- **Spark detection layer row, clause (4) — APPLICABLE, not "not triggered".** An earlier draft of
  this ledger stated this row was "not triggered" because this PR touches no `spark_engine.*`/
  `spark_mechanism.*`/`guardian_spark_*` file and calls neither of `hard_exit.hpp`'s
  `wait_for_workers_to_drain()`/`OrphanExitGuard` by name. **That was a truth defect, caught in
  adversarial review**: `log_handoff.cpp` `#include`s `hard_exit.hpp` and calls
  `hard_exit(kLogTeardownExitCode)` at two sites (`teardown()`'s catch-all and its
  `ShutdownDeadlineGuard`-default action) implementing exactly the pattern clause (4) governs —
  "`hard_exit()` rather than race teardown against an unjoinable worker" — and the row's own
  "Loaded by" column lists `hard_exit.hpp` as a trigger path regardless of which specific primitive
  in that file is used. **Applicability proof (post-fix):** the unjoinable-worker case here is
  `~spdlog::details::thread_pool()`'s blocking join, guarded exactly as clause (4) requires — see
  the `DrainGate`/`ShutdownDeadlineGuard` rows above for the corrected mechanism (the drain-reader
  lease closes the one interleaving, found and reproduced by both #4666 PR-1 adversarial reviewers,
  where an earlier revision let that blocking join escape onto an unwatched thread). This row does
  NOT concern `spark_engine.*`/`guardian_spark_*`/`GuardianDetachedWorkerRole` (this diff touches
  none of those and arms no Spark mechanism) — it concerns the shared `hard_exit.hpp` primitive
  clause (4) names, which this diff DOES use, correctly, after the fix above.
- Durable agent command idempotency row: not triggered — no `command_dedup_store.*`/Subscribe command
  loop code is touched.
- `common/include/` firewall: not triggered — `log_handoff.{hpp,cpp}` lives in `agents/core/src/`, not
  `common/include/`.
- Resource ownership / RAII (`docs/cpp-conventions.md`): every new owner above is either a `shared_ptr`
  with a single, clearly-stated release point, or a plain atomic/mutex-guarded scalar. No raw `new`/
  `delete`, no manual thread join outside `~thread_pool()`'s own (spdlog-owned, unmodified) join, no
  borrowed `string_view`/`span` stored past its source's lifetime.
- Known and recorded, not resolved here (PR-2's job): nothing in the shipped binary installs, calls, or
  tears down this primitive yet — `main.cpp`, `service_win.cpp`, `guardian_engine.cpp`, and
  `guardian_spark_runtime.cpp` are byte-for-byte unchanged by this PR. The synchronous-logging hazard
  this primitive exists to retire (`docs/spark-flip-gate.md` section 7) therefore remains exactly as it
  was before this PR until PR-2 lands.
