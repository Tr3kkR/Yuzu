# Resource Ledger - #4666 PR-1 bounded async log hand-off primitive

This ledger lists every thread, queue buffer, sink wrapper, and lock the PR-1 diff introduces, with
its owner and release path, for `agents/core/src/log_handoff.{hpp,cpp}`. A Resource Ledger is a
policy-floor artifact (CLAUDE.md standing rule 2), so it is a standalone file rather than a line in a
PR description. Nothing else changes in this PR — no production call site installs this primitive
yet (`main.cpp`/`service_win.cpp`/`guardian_engine.cpp`/`guardian_spark_runtime.cpp` are all
untouched; that wiring is PR-2). Format follows
`docs/resource-ledgers/spark-criterion10-timing-instrumentation.md`.

## `agents/core/src/log_handoff.{hpp,cpp}`

| Resource | Owner | Acquire | Release | Failure path |
|---|---|---|---|---|
| `spdlog::details::thread_pool` (one bounded queue + one worker thread) | `LogHandoff::pool_` (`std::shared_ptr`), constructed directly via `std::make_shared` — **never** `spdlog::init_thread_pool()`, so no spdlog registry co-owns it | `LogHandoff::create_with_sinks()`, after every earlier throwing step has already succeeded (sinks wrapped, error handler bound) | `LogHandoff::teardown()`'s T1 (`pool_.reset()`); `~thread_pool()` posts a `terminate` message under the `block` policy and **joins** its one worker | A healthy sink drains in order and the join returns promptly. A wedged sink means the call simply does not return; bounded by the `ShutdownDeadlineGuard` `teardown()` constructs around T1–T3 (`kLogTeardownGrace` 2 s default), which fires `hard_exit(kLogTeardownExitCode=5)` on the WHOLE PROCESS if the grace elapses — see the header's TEARDOWN CONTRACT for why this differs from the plan's original "caller wires an external watchdog" phrasing (U5's own requirement pins the self-contained design). `~LogHandoff()` runs `teardown()` if it was never called explicitly (fail-closed, matching `OrphanExitGuard`). |
| **Fixed RSS cost of the pool's queue — NOT proportional to traffic.** `spdlog::details::circular_q` pre-allocates all `kLogQueueCapacity + 1` (8193) slots **at `thread_pool` construction**, each slot a `spdlog::details::async_msg` (`sizeof == 408` bytes on x64, measured against the vendored spdlog 1.17.0 headers: a `log_msg_buffer` — four owning `std::string`s for logger name/payload/short-filename/funcname plus the scalar `log_msg` fields — an `async_msg_type`, and an `async_logger_ptr`). | The `std::vector<async_msg>` inside `circular_q`, owned transitively by `pool_` above | Same moment as the pool itself — this is not a high-water mark, it is paid in full up front | Same as the pool's own release | 8193 × 408 bytes ≈ **3.35 MiB**, always, for the life of any constructed `LogHandoff` — including one built only for a unit test. This is a corrected fact from the plan's final review (the original v1/v2 draft undercounted it as "~6 MB, only under load"); PR-2's own resource-ledger update and `docs/user-manual/server-admin.md` must both state the real figure again when the primitive is actually installed in the shipped binary. Payload bytes beyond the fixed per-slot allocation (a queued message's formatted text) are additional, unbounded by this primitive, and are measured on the rig in a later PR — never asserted here. |
| `spdlog::async_logger` (name `""`, `overrun_oldest`) | `LogHandoff::logger_` (`std::shared_ptr`) | Same `create_with_sinks()` call, immediately after the pool | `teardown()`'s T3 (`logger_.reset()`) | Holds only a `std::weak_ptr` back to the pool (never a cycle). `sink_it_`/`flush_` throwing (pool gone, formatter/allocation exception) routes to the non-I/O error handler below, never escapes uncaught into caller code (spdlog's own `SPDLOG_LOGGER_CATCH`). |
| `StallObservableSink` wrapper, one per caller-supplied inner sink | `LogHandoff::wrapped_sinks_` (`std::vector<std::shared_ptr<StallObservableSink>>`); each wrapper owns its inner `spdlog::sink_ptr` by `shared_ptr` | Same `create_with_sinks()` call, one per element of the caller's `sinks` vector | `teardown()`'s T3 (`wrapped_sinks_.clear()`), which drops the last reference to both the wrapper and (transitively) its inner sink — final inner-sink destruction (e.g. a rotating file sink's `fclose()`) therefore also runs under T1–T3's watchdog | The wrapper's own state is two plain atomics (`in_flight_` counter via an RAII `WriteGuard`, `started_at_ticks_`) — no lock, no allocation, cannot itself fail. `log()`/`flush()` forward to the inner sink and let its exception propagate (the RAII guard still decrements on unwind). `set_pattern()`/`set_formatter()` forward unconditionally (the v1→v2 regression the final review caught — dropping this silently reverts `--log-format json` to the default text pattern; pinned by unit test U-json). |
| Non-I/O error handler state (`LogHandoff::ErrorState`: a `std::mutex` guarding a count + a 256-byte-truncated last-message string) | `LogHandoff::error_state_` (`std::shared_ptr<ErrorState>`), captured by value into the `set_error_handler` lambda | Same `create_with_sinks()` call | Object lifetime ends when both `LogHandoff::error_state_` and the logger's own captured copy (inside `custom_err_handler_`, released at `logger_.reset()` in T3) drop | Reached **concurrently** from the pool's one worker thread (a sink `log()`/`flush()` throw) and from any producer thread (a formatter/allocation exception, or "pool gone") — this is why it is a plain `std::mutex`, not a lock-free/single-writer scheme (a spec bug in an earlier draft, corrected in the final review). The handler itself is wrapped in its own `try`/`catch(...)` so an allocation failure while recording the error message cannot escape back into spdlog's error-handling machinery. |
| Global drain-lookup slot (`DrainHandle`: `owner` raw-pointer identity tag + `std::weak_ptr` to the pool/logger/each wrapped sink) | File-local `std::shared_ptr<DrainHandle>` behind a function-local-static `std::mutex`, in `log_handoff.cpp`'s anonymous namespace — no header exposure | `LogHandoff::register_global_drain_handle()`, called once at the end of a successful `create_with_sinks()` | `LogHandoff::clear_global_drain_handle()`, called as the FIRST step of `teardown()` (T0), identity-checked against the calling instance so a newer instance's registration is never clobbered by an older one's teardown | Holds **only weak references** — `drain_log_bounded()` (the free function PR-2 wires into the abort paths) locks a temporary strong ref for the minimum span of each read and drops it immediately, specifically so it can never become the thread responsible for `~thread_pool()`'s blocking join. Documented residual: in the narrow window where `drain_log_bounded()` races a concurrently in-flight `teardown()` and *does* end up holding the pool's last reference for an instant, releasing it can trigger that blocking join on `drain_log_bounded()`'s own calling thread — exceeding its own `wait` bound in that rare case. The PROCESS-WIDE safety property still holds even then (`teardown()`'s own watchdog fires regardless of which thread is blocked); only this function's individual bound can, rarely, be exceeded. |
| `LogHandoff::construction_fault_for_test_` (`static inline std::atomic<bool>`) | Process-wide, test-only | Set by `set_construction_fault_for_test(true)` | Auto-consumed (reset to `false`) by the very next `create_with_sinks()` call, so it cannot leak into an unrelated later test | Production code never sets this; it exists purely to exercise the pool/logger-construction-failure return path without depending on the OS actually refusing to create a thread. |
| `ShutdownDeadlineGuard` (from `shutdown_deadline_guard.hpp`, reused unmodified) — a detached watchdog thread | Local to `teardown_impl()`'s stack frame; the watchdog's own detached worker thread is spawned via `io_detail::spawn_detached` (that primitive's own established orphan-exit contract, unchanged by this PR) | First statement of `teardown_impl()`, after T0's deregistration | RAII: the guard's destructor calls `cancel()` when `teardown_body()` (T1–T3) returns normally, before `teardown_impl()`'s own stack frame unwinds | If `teardown_body()` never returns (a genuinely wedged sink), the watchdog fires its action — `hard_exit(kLogTeardownExitCode)` in production, or a caller-supplied test callback via `teardown_with_action_for_test()` — after the grace elapses; the CALLING thread of `teardown()` remains blocked inside T1's `pool_.reset()` regardless (the watchdog terminates the whole process in production; the test-action variant is what lets U5 observe the deadline firing without actually killing the test binary — the test then still has to release the gate itself so the calling thread's own `join()` can complete). |
| `GatedCaptureSink`/`ThrowOnceSink` (test-only spdlog sink doubles, `tests/unit/test_log_handoff.cpp`) | Test-local `std::shared_ptr`s | Constructed per `TEST_CASE`/`SECTION` | Destructor runs once every `shared_ptr` owner (the test's own copy, if not explicitly dropped, plus the `LogHandoff`'s wrapped copy) releases | `GatedCaptureSink`'s pause gate is a `std::mutex`+`std::condition_variable`; its `closed_flag()` is a SEPARATE `shared_ptr<std::atomic<bool>>` control block (not `this`-bound) specifically so a test can observe "was the sink object actually destroyed" after dropping every `shared_ptr<GatedCaptureSink>` it holds (U4). No production code path creates either double. |

## Trigger rows and invariants this change was checked against

- Spark detection layer row: not triggered. This PR touches no `spark_engine.*`/`spark_mechanism.*`/
  `guardian_spark_*` file, does not call `hard_exit.hpp`'s `wait_for_workers_to_drain`/`OrphanExitGuard`,
  and adds no `mtx_` acquisition reachable from a Spark worker/callback.
- Durable agent command idempotency row: not triggered — no `command_dedup_store.*`/Subscribe command
  loop code is touched.
- `common/include/` firewall: not triggered — `log_handoff.{hpp,cpp}` lives in `agents/core/src/`, not
  `common/include/`.
- Resource ownership / RAII (`docs/cpp-conventions.md`): every new owner above is either a `shared_ptr`
  with a single, clearly-stated release point, or a plain atomic/mutex-guarded scalar. No raw `new`/
  `delete`, no manual thread join outside `~thread_pool()`'s own (spdlog-owned, unmodified) join, no
  borrowed `string_view`/`span` stored past its source's lifetime.
- Known and recorded, not resolved here (PR-2's job): nothing in the shipped binary installs, calls, or
  tears down this primitive yet — `main.cpp`, `service_win.cpp`, `guardian_engine.cpp`, and
  `guardian_spark_runtime.cpp` are byte-for-byte unchanged by this PR. The synchronous-logging hazard
  this primitive exists to retire (`docs/spark-flip-gate.md` section 7) therefore remains exactly as it
  was before this PR until PR-2 lands.
