- MCP Streamable HTTP: `GET /mcp/v1/` is now a live SSE channel — heartbeats, `Last-Event-ID` resume from a bounded per-session replay ring (a cursor past the window gets a `404` and re-initializes; never a silent gap), per-tick credential re-validation (a revoked credential ends a *live* stream; an unreachable auth store buys a bounded grace window instead of cutting every stream at once), and concurrency caps so held-open streams cannot starve plain REST. A second `GET` on a session takes over the older one, so a client reconnecting across a dead connection is never locked out by its own zombie. New flags `--mcp-max-streams` (16), `--mcp-max-streams-per-principal` (4), `--http-worker-threads` (auto; the defaults reproduce the previous implicit pool exactly).
