- `autoruns`: fixed a false-confident `disabled` report for systemd user-timer enablement when a wants-directory scan was capped or hit a read error — the plugin now reports `unknown` instead of guessing. Windows Startup-folder detection now follows a profile's redirected `User Shell Folders\Startup` value instead of always assuming the default path. Task Scheduler XML parsing moved from an ad-hoc scanner to libxml2 (also fixing a stale-encoding-declaration edge case).
- `autoruns`: Linux root-scheduled file detection (`cron.hourly`/`daily`/`weekly`/`monthly`, `/etc/rc.local`) now tests the file's own owner/group/other execute bits instead of `access(X_OK)`, which answered whether the agent's own unprivileged identity could execute the file rather than root's scheduler — a root-owned mode-0700 script was previously dropped from the collector's rows while the source still reported `supported`; `/etc/rc.local`'s eligibility check also now reuses the same `stat()` result `read_file_bounded` already took instead of a second redundant syscall.
- `autoruns`: every Linux collector (cron.d, run-parts periodic dirs, user crontabs, at spool, XDG user autostart, both systemd-timer scopes) now accumulates every real acquisition failure — not just permission-denied — into the source's `constrained` status, including a genuine wants-directory scan failure during systemd-timer enablement checks and a crontab line the parser rejects (`malformed`, every other valid line in the same file still kept); the crontab parser also now recognizes spaced `VAR = value` environment-variable assignments it previously misclassified.
- `autoruns`: Linux `list` now surfaces any per-source `constrained` status into the plugin's typed ABI4 CC-07 result status (`CONSTRAINED`/`PARTIAL`), so a fleet-scale consumer reading only the typed field, never the text stream, still learns of a real acquisition failure.
