- **Guardian/Spark rule ids and Spark keys are neutralised before they reach a log line, closing an operator-authored log-injection exposure (CWE-117, #4665).** A rule id containing a newline could previously forge a whole physical log line, and one containing a space or `=` could forge extra tokens on the same line, in log statements across the legacy file/registry/service guards, `SparkEngine`, the Guardian engine, and the server's Guardian push/event-store code — none of these sites validated or neutralised the value before printing it, unlike the existing `Guardian T_*` diagnostic lines. Every such print site now wraps its rule id, path, registry hive/key, value type, service/agent identifier or unit name through a shared neutraliser (`common/include/yuzu/log_token.hpp`) before it is written. **`POST /api/v1/guaranteed-state/rules` and MCP `create_guardian_rule` now reject a non-conforming `rule_id` at creation** (`400` on REST, a JSON-RPC error on MCP, both audited as `denied`) instead of accepting anything non-empty — a rule id must match `[A-Za-z0-9._-]+` and be at most 256 bytes; this was already the documented contract, now actually enforced. **Breaking — for a fleet with a pre-existing non-conforming `rule_id`, this is a hard cutover, not a migration:** validation is create-only and not retroactive by itself, but the upgraded agent's `full_sync` unconditionally rebuilds its entire active rule set from whatever the server's push contains, and the server-side push builder now excludes any non-conforming legacy row from every push it builds (both sides log and meter it) — so the first `full_sync` an upgraded agent receives **permanently disarms** every rule whose `rule_id` predates this release and doesn't conform to `[A-Za-z0-9._-]+`/256 bytes. Every other rule in scope is unaffected. Find and fix these BEFORE upgrading — `GET /api/v1/guaranteed-state/rules` lets you filter for a non-conforming `rule_id` — see `docs/user-manual/upgrading.md`'s Behaviour change entry for the exact detection query and which delete surface (MCP `delete_guardian_rule`, REST `DELETE`, or a direct database delete) reaches which shape of violation.
