- **MCP streamed POST (SSE-on-POST) lands, and ships OFF.** `execute_instruction` callers that supply a `_meta.progressToken` and send `Accept: text/event-stream` can receive progress on the POST response itself rather than the session's GET channel (ADR-1005 Decision 15, track 2f PR 3b). The machinery is complete and reviewed, and it is gated behind **`--mcp-enable-streamed-post` (default off)**. It landed with two bounds defects open against it — **#2739**, the 120 s response cap was arbitrated only on a pass that found neither progress nor a terminal, so a record whose progress mailbox was non-empty on every tick never reached it; and **#2740**, a committed-but-undelivered streamed final held one of the session's four streamed-POST admission slots, so four dropped connections locked that session out of streaming. Both are FIXED in this same release (see the entries for #2739 and #2740); turning the flag on by default is a separate rung and has not happened yet. Neither affects plain JSON-RPC POST, the session lifecycle, or the GET channel. This is the same shape as Spark's `prefer_spark_`: land the machinery dormant, cut over where the invariants hold.
