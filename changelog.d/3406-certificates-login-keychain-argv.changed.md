- **`certificates` plugin reads the macOS login keychain without a shell, and spawns one fewer process.** The console user's login-keychain enumeration (`list`/`details` with `store=login`/`all`) now runs `security find-certificate` under its `launchctl asuser`/`sudo -u` session hop as a pre-split argv vector through the bounded subprocess runner — the `/bin/sh -c` wrapper is gone. The shell's only remaining job was `~user` tilde expansion, now performed in-process via `getpwnam_r`, which consults the same Directory Services database the shell did, so any resolvable account — relocated and network home directories included — reads the identical path. That same lookup also supplies the console user's uid, which removes a second subprocess (`id -u`) that had been asking the same database for it. Behaviour changes in one place only, in the safe direction: where an unresolvable account previously produced an opaque `security` failure, the action now reports an honest "home directory unresolved" result instead. This promotes the leg from rung 3 (governed-shell exception) to rung 2 under ADR-3002 and retires the plugin's last shell-payload subprocess (#3406).
