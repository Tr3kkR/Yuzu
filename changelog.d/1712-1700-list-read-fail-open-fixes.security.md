- **Dashboard/workflow response readers and MCP `get_agent_details` close the last ADR-0017 list-read fail-open gaps (#1712, #1700).** The dashboard `/fragments/results` table and the workflow executions-drawer now apply the same per-agent management-group scope filter as the REST/MCP response readers (#1634/#1711) — a corrupt or unreachable RBAC store yields zero rows instead of the whole fleet's output. MCP `get_agent_details` now enforces management-group scope the same way `summarize_working_set kind=agent` does (#1653): an `agent_id` outside the caller's management group renders identically to "Agent not found," so existence itself is never disclosed. The dashboard results summary ("N results across M agents", and the Create Group affordance) now counts only in-scope agents, so a confined operator is no longer told how many agents outside their management group answered the command.
