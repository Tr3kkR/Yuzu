- **Pull-request CI skips test families a PR cannot reach, and splits the Linux Postgres shards across two jobs.** A PR whose changed paths cannot reach the server tests, or the agent and tar tests, no longer runs them on any of the three legs (the agent unit test alone is ~197 s on Windows and ~170 s on macOS); `docs`, `proto` and `gateway` always run, and a push to dev or main always runs every suite. The decision is `scripts/ci/affected-suites.sh`: fail-closed, rename-aware, and aware of files tests read at run time, with its class table checked against the real build by `scripts/ci/check-suite-input-closure.py`. On a PR the Linux leg is now two jobs: `Linux gcc-15 debug` (non-pg suites plus shards G, I, K, L) and a new `Linux gcc-15 debug (pg B)` (the other eight shards), each on its own runner and per-runner Postgres. `tests/meson.build` labels every pg shard `server-pg-a` or `server-pg-b`, and `check-pg-shard-partition.py` fails a shard with neither. A repo admin must add `Linux gcc-15 debug (pg B)` to the `dev` ruleset's required checks after this merges. See `docs/ci-architecture.md`, "PR-time test selection".
