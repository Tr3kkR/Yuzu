- **CRL publishing is safe across server replicas (HA WS-6 slice 6.1, #4126).** Every CRL publish (the boot-time publish, an operator revoke, and the freshness re-publish) now runs as one Postgres transaction under a lock on the CRL table. Replicas sharing a database publish strictly increasing CRL numbers with no duplicates or gaps, and each CRL contains every revocation the previous one did. Previously two replicas publishing at the same moment could pick the same number, and one publish would fail. `GET /api/v1/ca/crl` is not blocked while a publish is in progress. A publish that cannot get the lock within the database lock timeout fails honestly (`crl_republished:false` plus the existing failure audit and `yuzu_server_ca_crl_publish_failures_total`) and uses up no number.
