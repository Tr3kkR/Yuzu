- **The OIDC client secret is no longer written to the server log or returned by `GET /api/config`.** When the secret was set through Settings it was stored in runtime-config as plaintext (an accepted at-rest position until ADR-0010 envelope encryption reaches that store) — but the value was also emitted twice: written verbatim into `yuzu-server.log` by the startup override pass on every boot, and returned in the `overrides` object of `GET /api/config`, a route gated only on `Infrastructure:Read`. Both contradicted the settings UI, which has always rendered the same field as `********`. A third and worse sink was found in review: `PUT /api/config/:key` wrote the plaintext value into the **audit detail**, which is durably retained and readable by every role seeded `AuditLog:Read` — `Operator` among them — and which cannot be rotated away afterwards. All three are fixed. `GET /api/config` now **omits** a secret's value entirely and reports `is_set` instead of a placeholder, because a placeholder is itself a legal value and a config-as-code client reading and writing it back would silently overwrite the real secret; `updated_by` and `updated_at` are still returned. `RuntimeConfigStore::get_all()` now redacts by default and plaintext requires the explicitly-named `get_all_with_secrets()`, so an emitter that does not think about secrets gets the safe behaviour — opt-in redaction is what allowed the audit-row leak to survive the first fix.
