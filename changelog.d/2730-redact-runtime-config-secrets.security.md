- **The OIDC client secret is no longer written to the server log or returned by `GET /api/config`.** When the secret was set through Settings it was stored in runtime-config as plaintext (an accepted at-rest position until ADR-0010 envelope encryption reaches that store) — but the value was also emitted twice: written verbatim into `yuzu-server.log` by the startup override pass on every boot, and returned in the `overrides` object of `GET /api/config`, a route gated only on `Infrastructure:Read`. Both contradicted the settings UI, which has always rendered the same field as `********`. Both now emit `<redacted>`; `updated_by` and `updated_at` are still returned, so an operator can see that the secret is set and who set it. A new `RuntimeConfigStore::is_secret_key()` is the single predicate every emitter consults, with a test tripwire that fails if a future credential-shaped key is added to the allowed-key list without being registered as secret.
