- When an MCP session's replay-ring pin slots are exhausted, the oldest pinned terminal now yields its eviction exemption instead of the newest terminal being committed without one. Exhaustion should not happen — the bridge admits streamed records against the same count the slot array is sized to, so a full set means admission accounting has drifted — but the old fallback sacrificed the wrong frame: the newest result is the one a client is most likely still waiting to resume, while the oldest has almost certainly been consumed. The drift is reported by the new `yuzu_mcp_stream_pin_displaced_total`, which is alertable on `> 0` and inherits that reading from `yuzu_mcp_stream_final_unpinned_total`.
