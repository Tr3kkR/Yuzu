- **The remaining 6 stores' legacy-SQLite backfill mechanism has been retired** (`migrate_from_sqlite()` — WebhookStore, CaStore, InventoryStore, RbacStore, ManagementGroupStore, QuarantineStore), closing tracking issue #3623 and following the same ADR-0009 fresh-start-by-default amendment as the 12 stores retired previously (#3898): no production Yuzu fleet has ever run a pre-Postgres build of any of these stores either, so there was never real legacy data to protect — including for the three stores whose backfill was itself MANDATORY-classed (RbacStore's `rbac_enabled` flag, ManagementGroupStore's confinement hierarchy, QuarantineStore's active containment records), a decision reopened and explicitly reconfirmed for each rather than defaulted by uniformity with the other stores. Each store's boot path now runs a lightweight detect-and-warn (`legacy_sqlite_probe::warn_if_legacy_rows` — counts rows in the old SQLite file if present and logs a warning, never copies data, never blocks boot); WebhookStore's legacy file may still hold a plaintext signing secret, so its boot path also hardens it to 0600 (main file plus any `-wal`/`-shm` sidecars, via the new shared `legacy_sqlite_probe::harden_legacy_file_0600` helper) before probing it, and no longer moves it aside afterward — a legacy file, if found, now stays at its original path. InventoryStore's `delete_agent()` also no longer erases anything from a legacy `inventory.db`, since the erasure branch's sole reason to exist was the backfill it served. The associated `yuzu_server_{rbac,mgmt_group,webhook}_backfill_total` Prometheus metrics and their alert rules, two dedicated ops-runbooks (RbacStore, QuarantineStore), and each store's `docs/user-manual/upgrading.md` mandatory-backfill section have been removed to match. AuditStore's backfill remains the sole permanent exception (audit evidence can't be regenerated) — every other already-migrated store's `migrate_from_sqlite()` is now retired.
