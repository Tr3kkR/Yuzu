- MCP replay-ring pin slots are now a bounded LRU instead of a first-come-permanent reservation. A session's terminal frames are pinned so a late `GET` resume can still recover them after a ring wrap, but the only release path is a resume cursor acking past the id — so a client that read its results live and never reconnected held every slot for the life of the session, and from the fifth call onward each result was committed *without* that protection while `yuzu_mcp_stream_final_unpinned_total` fired during entirely ordinary use. A full slot set now displaces its oldest pin, keeping the most recent terminals recoverable, and the displacement is counted by the new `yuzu_mcp_stream_pin_displaced_total`.
