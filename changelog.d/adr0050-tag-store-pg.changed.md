- TagStore migrated to the PostgreSQL substrate (ADR-0050, schema `tag_store`): construction and the mandatory one-time `tags.db` backfill fail closed; every tag read is typed (a degraded store returns an error, never a silent empty result) and `tag:<key>` scope resolution now bulk-preloads and ABORTS evaluation on a degraded read instead of silently matching nothing/everything; REST/MCP tag surfaces answer 503 on a degraded store and 400 on caller errors, and a failed tag write is reported instead of returning success. Backfill row conflicts are direction-aware on `updated_at` (a legacy row ahead of Postgres refuses the boot rather than silently discarding the later write) — recovery runbook: `docs/ops-runbooks/tag-store-backfill-recovery.md`.
