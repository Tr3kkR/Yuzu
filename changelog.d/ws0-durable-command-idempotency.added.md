- The agent now records command idempotency durably (SQLite `command_dedup.db`), so replay protection survives an agent restart, not just a reconnect. A redelivered command replays its **original terminal outcome** (success, output, exit code) instead of a bare `REJECTED`, closing the "effect-once, result-maybe-lost" gap where a lost acknowledgement discarded a completed command's real result. A command that was still executing when the agent stopped is reported as in-progress on redelivery and never silently re-executed (HA delivery-matrix WS-0, ADR-2002; effectively-once, not exactly-once).
