- **Pull-request CI skips test families a PR cannot reach, and splits the Linux Postgres shards across two legs.** A PR into dev whose changed paths cannot reach the server tests, or the agent and tar tests, no longer runs them on any of the three legs (the agent unit test alone is ~197 s on Windows and ~170 s on macOS); `docs`, `proto` and `gateway` always run, and a push to dev or main, or a PR into main, always runs every suite. The decision is `scripts/ci/affected-suites.sh`, fed the paths read from the merge commit the run builds (`scripts/ci/pr-changed-paths.sh`, so it sees both sides of a rename and has no file-count cap): fail-closed, and aware of files tests read at run time. Its class table is checked against the real build on the Linux and macOS legs by `scripts/ci/check-suite-input-closure.py`, and the `ci.yml` steps that decide and apply it are pinned by `tests/shell/test_suite_selection_wiring.sh`. On a PR the Linux work is two legs, `Linux gcc-15 debug (pg A)` (the non-pg suites plus shards G, I, K, L) and `Linux gcc-15 debug (pg B)` (the other eight shards), each on its own runner and per-runner Postgres, and the required `Linux gcc-15 debug` check is a gate job that passes only when every leg does, so no ruleset change is needed. The docs-only gate reads the same list and now also builds a PR whose docs change touches a file a test reads, or that renames code into `docs/`. See `docs/ci-architecture.md`, "PR-time test selection".
