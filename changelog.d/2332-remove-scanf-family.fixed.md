- **Removed every scanf-family call from agent and server code (#2332 follow-up).** glibc 2.38 redirects `fscanf`/`sscanf` to versioned `__isoc23_*` symbols, so Linux binaries built on a new-glibc toolchain refuse to load on RHEL-era glibc. All 8 call sites (the `fs.nr_open` fd-ceiling read, `/proc/net/dev` throughput counters, the mapdrive flexible-timestamp and Security-log event/logon-type parsers, and the TAR tree timestamp query param) now use `std::fgets` + `std::strtol`-family parsing with end-pointer checks, behaviour-identical including scanf's width caps and whitespace handling; the two previously-unchecked `sscanf` calls in the Security-log parser now check their parse explicitly.
