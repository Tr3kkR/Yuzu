- **Plugin README standard, generator, capture tool and gates (`docs/plugin-readme-standard.md`).** Every agent plugin now documents itself beside its code: `agents/plugins/<name>/README.md` with eight fixed sections — what it does, how it works (with a data-flow diagram), per-OS capability (support, rung, mechanism per action, from the CI-verified capability matrix), privileges, the data contract (inputs, output columns with vocabularies and per-OS availability, result status, where the data goes), real sample output per OS, caveats, and source paths. `tools/plugin-doc-gen` regenerates the generated fences, the user-manual plugin index, the docs-site navigation and a machine manifest per plugin (`content/plugin-docs/<name>.json`) from the committed sources with no build; `tools/plugin-capture` runs a built plugin through the agent's real `LocalDispatcher` and writes a stamped sample file whose leg-hash the gate re-checks when a leg's mechanism or column schema changes. Gates: `tests/test_plugin_readmes.py` (README-existence ratchet, section contract, byte-match of every generated artefact, capture presence and freshness) in the meson `docs` suite, and a docs-lint touch rule that fails a PR changing `agents/plugins/<x>/src/**` without touching the README unless the body states `docs-unchanged: <section> — <reason>`. The definition DSL gains four optional column keys (`description`, `values`, `example`, `platforms`). For agentic clients the manifests are embedded in the server and served as `GET /api/v1/discover/plugin-docs` and the MCP resource `yuzu://plugin-docs` (byte-identical, `Infrastructure:Read`), and `discover_plugins` / `GET /api/v1/discover/plugins` (catalog version 2 → 3) joins a per-plugin `docs` summary or an explicit `null`. The docs site renders every adopted README under `/plugins/<name>/`. Pilots: `disk_actions` and `firewall`, with real captures on Windows, macOS and Linux; the remaining plugins follow in the retrospective sweep.
