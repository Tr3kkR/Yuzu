- The server **RBAC store** (the authorization substrate — roles, permission grants, groups, and the RBAC-enabled flag) now runs on PostgreSQL (schema `rbac_store`) instead of a per-server SQLite `rbac.db` (ADR-0041, continuing ADR-0006). **RBAC config is preserved** across the cutover by a one-time, fail-closed, resumable backfill on first boot (the `rbac_enabled` flag is migrated first and read-back-verified, so a fleet that enabled RBAC stays enabled); the legacy `rbac.db` is moved aside once verified. **Authorization reads now fail closed** — a degraded/unreachable store denies rather than the prior fail-open on a corrupt `rbac.db` — and authorization is fleet-consistent across replicas via a durable generation token (bounded sub-second cross-replica staleness). New metrics `yuzu_server_rbac_read_degrade_total` and `yuzu_server_rbac_backfill_total` are exported. On a large `rbac.db`, first boot takes longer while the backfill streams; widen the startup/health-probe budget (see the upgrading guide).
