- **New read-only `browser_policy` agent plugin — enterprise-managed Chrome, Chromium and Edge policy inventory.** `policies` returns one row per configured policy: the browser, whether the policy is mandatory or recommended, its scope, its name, its typed value and the file it came from. On Linux the rows come from the managed and recommended JSON policy files under `/etc/opt/chrome`, `/etc/chromium` and `/etc/opt/edge`, read in-process (no subprocess) without following symlinks. A host with no managed policy returns zero rows with a clean result status; a policy file that cannot be read or parsed makes the result `CONSTRAINED` instead of reading as absent. The Windows registry and macOS Managed Preferences legs are planned and ship separately: until then `policies` on those hosts returns zero rows with an explicit `UNAVAILABLE`/`PARTIAL` result status (provenance `windows:planned` or `macos:planned`), so a host that was not inspected never reads as having no policy. Classified under the `Inventory` securable (`Inventory:Read`); it carries no kill switch because it reads administrator-authored configuration, not personal data.
