- **`scripts/ci/ensure-postgres.sh` path 1: fail instead of falling back on a manifest-vouched Postgres fault.** A manifest-vouched `psql` (`YUZU_CI_PSQL`, exported by `deploy/windows/Assert-Toolchain.ps1 -ExportCiEnv`) has already proven the exact `psql.exe`/cluster pair earlier in the same job, so a `SELECT 1` failure against it — for agent 0/the base cluster (which had no probe-with-retry at all before this) as well as any further agent — is now retried briefly and then fails the job outright, instead of falling back onto the shared agent-0 cluster (the #2094 cross-job contention the per-agent split exists to avoid). The pre-existing behaviour for an *unprovisioned* box (a `PATH`-sourced or absent `psql`) is unchanged: it still warns with a `::warning` and falls back to the shared cluster — that fallback was never silent, only the un-probed manifest-vouched case above is new. Only a `psql` proven by the same job's toolchain-manifest check (loopback host, no `PGHOST`/`PGHOSTADDR`/`PGSERVICE`/`PGPORT` override, an in-session identity/config-parse check on the heal session itself) is ever healed with `ALTER SYSTEM`; every other case is report-only. The same manifest-vouched fail-instead-of-fallback rule now also covers a multi-agent runner's pre-set DSN that can't be safely derived to a per-agent port (not a plain URI): it fails the job rather than silently falling back to the shared, un-isolated DSN.
