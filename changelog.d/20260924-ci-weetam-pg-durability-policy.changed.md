- **`scripts/ci/ensure-postgres.sh` path 1: fail instead of falling back on a manifest-vouched Postgres fault.** A manifest-vouched `psql` (`YUZU_CI_PSQL`, exported by `deploy/windows/Assert-Toolchain.ps1 -ExportCiEnv`) has already proven the exact `psql.exe`/cluster pair earlier in the same job. A `SELECT 1` failure against it is therefore retried briefly and then fails the job outright, for agent 0/the base cluster (which had no probe-with-retry) and for any further agent alike: a further agent no longer falls back onto the shared agent-0 cluster (#2094, the cross-job contention the per-agent split exists to avoid), and agent 0 no longer exports an unchecked DSN. The same rule covers a multi-agent runner's pre-set DSN that cannot be safely derived to a per-agent port (not a plain URI): the job fails rather than silently falling back to the shared, un-isolated DSN. An *unprovisioned* box (a `PATH`-sourced or absent `psql`) is unchanged: it still warns with a `::warning` and falls back to the shared cluster. A cluster is healed with `ALTER SYSTEM` only under GitHub Actions, through that manifest-vouched `psql`, on a loopback host named by a plain-URI DSN with no `PGHOST`-family override, and only after the heal session's identity and config-parse checks pass; other drift is report-only.
