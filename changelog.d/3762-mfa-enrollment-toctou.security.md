- **MFA enrollment: concurrent double-verify can no longer orphan a recovery-code set.** `mfa_verify_enrollment`'s provisional→enrolled commit is now atomic with its own "not yet enrolled" precondition — the enrollment `UPDATE` carries `… AND mfa_enrolled_at IS NULL RETURNING id`, the same race-safe guard the recovery-code consume path uses. Two concurrent verifies of one enrollment code previously both stamped `mfa_enrolled_at` and both regenerated the 10 recovery codes (the loser's DELETE-all+INSERT deleting the winner's just-issued set), so a user who recorded the winning response's codes could be locked out of recovery. The losing verify is now graded "already enrolled" rather than a spurious "store unavailable" 503.
