- **Guardian file guards now follow a renamed or moved watched directory.** The guard re-arms its watch when the directory holding the guarded file (or, before that directory exists, its nearest existing ancestor) is renamed or moved, and evaluates the original path like any other change to it: a guarded file that is no longer there is reported as absent under `file-exists` rules that expect it present and under `file-hash-equals` rules, and changes made after the original path is recreated are detected. This behaviour also functions over SMB in testing, via a plain name-match fallback, but has not been validated against a production Windows/NAS file server.
