- **A revoked default server certificate now stays revoked across default-certificate regeneration (#4126).** Regenerating the built-in default certificates (for example after changing `--cert-san`, or when the leaf files are missing) purged their old inventory rows, including revoked ones. The revoked leaf was then accepted again by the server's revocation check and dropped from every later CRL. Revoked rows are now kept. This only protects revocations from now on: a revoked default leaf whose row was already purged cannot be re-revoked (its serial is no longer in the inventory, so `POST /api/v1/ca/revoke` returns 404). If you ever revoked a default server certificate — for example because its key may have leaked — and the default certificates have been regenerated since, treat that revocation as lost and re-root the internal CA (`docs/pki-architecture.md`, "Deliberate clean re-root").
