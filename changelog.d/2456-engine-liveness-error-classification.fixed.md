- Engine-principal liveness re-checks no longer arm their 5-10s failure backoff on a bare connection-pool acquire timeout alone (a briefly-saturated pool under unrelated load reads identically to a real outage at that point); the backoff now arms only on confirmed unreachability (the store closed, or a query actually ran and failed). A query failure's log line now names the real cause when PostgreSQL's SQLSTATE indicates a permanent schema or access-rule problem (missing table, revoked grant) rather than always reporting a retryable PG-availability condition.
