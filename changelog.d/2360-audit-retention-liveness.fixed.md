- New `yuzu_server_audit_retention_passes_total` counter and `YuzuAuditRetentionNotRunning` alert. Every other audit-retention metric only moves when something happens, so the one state none of them could express was retention not running at all - `audit.db` growing without bound with every counter at zero, `/healthz` reporting ok, indistinguishable from an idle server. That needs no fault to reach: the cleanup loop sleeps a full interval before its first pass, so a server restarting more often than the cleanup interval (60 minutes by default) never completes one. The counter increments on every pass attempted, whatever the outcome, so the alert can fire on the absence of increase.
