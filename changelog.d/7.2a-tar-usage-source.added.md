- **New TAR `usage` capture source — derived per-executable app-usage aggregate, enabled by default.** `usage` (backed by `$Usage_Live` / `$Usage_Daily`) is a derived fold over the existing `process` source: it pairs `started`/`stopped` process events into per-executable runs on the fast tick, with no collector or rollup SQL of its own (`run_usage_fold`, see `docs/tar-implementer.md` §8). **Ships on by default** (`usage_enabled=true`), joining `power` and `removable` as the third works-council-class source to diverge from the opt-in posture every TAR source added since 1.5 otherwise follows. The fold's boundary is strictly **forward-only**: coverage begins at the first tick after enablement or upgrade (`usage_coverage_since`), and process history from before that point is never retroactively folded. `usage_live` persists the owning `pid`/`user` for each open run and `usage_daily_user` persists a raw username per (day, executable) — both queryable via `tar.sql` — while `usage_daily` itself carries only a per-day `distinct_users` count, never a name. Set `usage_enabled=false` to opt out; existing `usage_daily`/`usage_live` rows stay queryable until they age out under their own retention windows.
