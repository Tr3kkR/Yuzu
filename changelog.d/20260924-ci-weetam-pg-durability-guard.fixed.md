- **Wee Tam CI: per-job Postgres durability-off guard and four-cluster fingerprint.** Fixed the Wee Tam (Windows) CI pool having no guard against durability-off drift on the native, pre-set-DSN Postgres clusters it uses (`scripts/ci/ensure-postgres.sh` path 1) — unlike the Docker path's tuning-label drift guard, and unlike agent 0, which was not even probed. Durability was previously applied only once, at provisioning (`deploy/windows/Provision-Windows-Runner.ps1`); a later drift on any of the four clusters surfaced only as a 700s `[pg]`-shard `TIMEOUT`. Every Windows job now reads `fsync`/`synchronous_commit`/`full_page_writes` from the cluster it is about to use before exporting the DSN and, only under GitHub Actions against a loopback host with a toolchain-manifest-vouched `psql`, heals a drifted setting with `ALTER SYSTEM` + `pg_reload_conf()` and a bounded re-read; elsewhere drift is only reported, never healed. `deploy/windows/Assert-Toolchain.ps1` now also prints a read-only, one-line durability-settings fingerprint for all four Wee Tam clusters on every run, so a drift is visible in seconds instead of as a shard timeout, and (opt-in, CI-only) exports the manifest-vouched `psql` path the new guard uses. A manifest-vouched per-agent probe failure is retried briefly and then fails the job outright, rather than falling back onto the shared agent-0 cluster and reintroducing the cross-job contention the per-agent split exists to avoid.
