# Codex Phase 1 — independent review

[CDX-P1-001]  MEDIUM · CONFIDENCE(hi) · PROVENANCE(compiled)
Throwing audit writes bypass the new fail-closed JSON-RPC/A4 response
- Location:  server/core/src/mcp_server.cpp:12100 (+ 12168, 12350, 12598, 12708, 12839, 12958, 13416); server/core/src/rest_audit.hpp:61
- Claim:     All eight new checks handle only an `AuditFn` false return, so an audit sink that throws after the mutation commits escapes before the promised JSON-RPC 503/A4 envelope is constructed.
- Evidence:  Each changed site invokes `audit_fn(...)` directly and only then tests `if (!audit_ok)`; `rest_audit.hpp:61-89` defines the shared `try_persist_audit` kernel specifically to catch `std::exception` and non-standard exceptions and convert them to `false`, and `mcp_server.cpp:3952-3963` says MCP audit calls route through that kernel so throwing audit functions are caught and returned as false.
- Scenario:  An authorized caller performs any engine-principal mutation → the store commit succeeds → allocation or another exception escapes the audit sink → the handler never reaches its `a4_error(503, ..., audit_ok=false)` branch, leaving the caller without the correlation/remediation/audit-gap response promised for this failure class.
- Inference: A throw is an audit-write failure just as surely as a false return; the codebase's own shared kernel explicitly models it that way. The mutation still does not return a normal success, but it violates the newly documented response contract and A4 recovery contract.
- Anchor:    `docs/agentic-first-principle.md` A4 (“Every failure response” includes code/message/correlation/retry/remediation) and A5 item 5 (self-recovering A4 errors); `docs/mcp-server.md` “Engine-principal mutation tools fail closed on an audit-persist failure” promises a JSON-RPC 503 with `audit_persisted:false` whenever the row cannot persist.
- Fix:       Route each domain success audit through `detail::try_persist_audit`, or introduce one local fail-closed audit helper used by all eight sites, and add a throwing-`AuditFn` regression test asserting the same 503/A4 body and secret withholding as the false-return case.

[CDX-P1-002]  MEDIUM · CONFIDENCE(hi) · PROVENANCE(static-read)
The live MCP tool descriptions omit the new audit-failure recovery behavior
- Location:  server/core/src/mcp_server.cpp:976-1183 (+ 1308-1359)
- Claim:     The machine-served `kTools[]` descriptions for the eight materially changed mutation tools still describe only their ordinary success/retry workflows and do not tell an agentic client that an audit failure can mean “committed but unconfirmed,” whether a secret was withheld, or which read/recovery action is safe.
- Evidence:  For example, `mint_engine_credential` says it “Returns the raw credential value exactly once,” while its new handler can commit the credential and return no secret; `rotate_engine_credential` describes retry behavior without the audit-failure re-serve rule; none of the eight descriptions contains `audit`, `audit_persisted`, or the new reconcile/do-not-retry instruction, while `docs/user-manual/mcp.md:468-476` now documents those distinctions for humans.
- Scenario:  An agentic worker discovers and drives the tool solely through `tools/list` → receives the new 503 after a committed mutation → follows only the served description (or its generic retry policy) and cannot distinguish safe read reconciliation from a duplicate/destructive recall.
- Inference: The omission is operationally material because the safe action differs by tool (read/reconcile, rotate rather than re-mint, bounded re-rotate, or never re-confirm); external prose is not a substitute for MCP-native context.
- Anchor:    `docs/agentic-first-principle.md` A5 items 2 and 5: tool descriptions must be decision-grade, include workflow chaining and what should precede/follow, and errors must be self-recovering; the document states machine-readable context must teach as much as English prose.
- Fix:       Update each affected `kTools[]` description with its concise audit-failure outcome and exact safe recovery; add a tools/list assertion for at least the credential and confirmation distinctions.

[CDX-P1-003]  MEDIUM · CONFIDENCE(hi) · PROVENANCE(static-read)
Audit documentation and source commentary still state the superseded set-and-proceed contract
- Location:  docs/user-manual/audit-log.md:184; server/core/src/mcp_server.cpp:11324-11339; docs/mcp-server.md:163
- Claim:     Two retained authorities say MCP mutations set-and-proceed/non-fatally surface `audit_persisted:false`, directly contradicting the new handler behavior and the newly added MCP posture paragraph; that paragraph also inaccurately says `mcp_audit("error")` records the outcome server-side even though it uses the same failing audit sink.
- Evidence:  `audit-log.md:184` says “over MCP the same failure is signaled non-fatally via audit_persisted:false”; the source block at `mcp_server.cpp:11324-11339` says plugin-config tools mutate-then-audit and cites `assign_engine_role` as the established set-and-proceed sibling, although plugin-config now audits before mutation and `assign_engine_role` now errors; `docs/mcp-server.md:163` says `mcp_audit("error") records the outcome server-side`, while `mcp_audit` at 3957 calls `try_persist_audit` on the same `audit_fn`, so an ongoing audit-store failure cannot durably record it.
- Scenario:  An operator or maintainer consults the audit-event catalogue/source contract → implements alerting or a sibling mutation using the stated nonfatal precedent → silently restores the behavior #3937 is intended to remove or expects an `mcp.*|error` row that cannot exist during the outage.
- Inference: Contradictory audit posture documentation is especially risky here because this change's purpose is contract alignment, and the stale source comment explicitly names one of the changed handlers as precedent.
- Anchor:    `docs/mcp-server.md` “Engine-principal mutation tools fail closed…” and ADR-1005 standing question (`docs/adr/1005-headless-platform-use-case-engines.md` Consequences) require audit behavior at the API to be truthful and consistent; otherwise judgment for documentation completeness.
- Fix:       Update `docs/user-manual/audit-log.md`, replace the stale plugin-config source comment with the current audit-before-mutate/fail-closed posture, and describe `mcp_audit("error")` as a best-effort attempt plus the existing out-of-band log/metric rather than a guaranteed server-side record.
