The startup CRL publication bypasses the newly wired leader gate
- Location:  server/core/src/server.cpp:7176 (+ server/core/src/server.cpp:7181; gated periodic duplicate at server/core/src/server.cpp:7831-7841)
- Claim:     every replica still publishes a new CRL during startup before the elector is constructed, so the change does not make all automatic CRL publication single-writer and concurrent starts can race `crlNumber` allocation.
- Evidence:  `run()` calls `if (!publish_crl())` at line 7181; `leader_elector_` is not constructed until lines 7336-7348; `publish_crl()` takes only the process-local `crl_publish_mu_` and calls `ca_store_->next_crl_number()` at lines 10397-10442; only the later freshness path checks `leader_gate_permits<background_job_class("ca.publish_crl")>` at lines 7831-7841.
- Scenario:  two server processes start against the same database at the same time → both execute the ungated startup pre-publication → both read/allocate the next CRL number before either records it → one publication conflicts/fails or two automatic publishers race despite `ca.publish_crl` being classified leader-only.
- Inference: the boot-time call is an automatic, non-operator invocation of the same state-mutating primitive; although it is a one-shot rather than a periodic loop, leaving it before election defeats the stated single-writer rationale for CRL numbering during the exact failover/rolling-start interval where replicas overlap. WS-6 may later make number allocation intrinsically safe, but this slice's attempt gate should already cover this automatic attempt.
- Anchor:    judgment (consistent with ADR-2002 §6's single-core singleton-work model and the routed concern's `ca.publish_crl` single-writer rationale, but those anchors explicitly name the background tick/loop and do not unambiguously classify the startup one-shot).
- Fix:       move the startup pre-publication until after leadership is acquired and guard it through `leader_gate_permits<background_job_class("ca.publish_crl")>`, or split/name a separately classified startup pass and make its cross-replica number allocation atomic.
